YOLO 방법 고찰
Yolo의 문제점은 입력 이미지를 7x7 크기의 그리드로 나누고, 각 그리드 별로 Bounding Box Prediction을 진행하기 때문에 그리드 크기보다 작은 물체를 잡아내지 못함

Multi Scale Feature Maps for Detection

그 다음 이렇게 추출된 피쳐맵을 컨볼루션을 거쳐 그 다음 층에 넘겨주는 동시에 Object Detection을 수행
단계별 피쳐맵에서 모두 Object Detection을 수행하는 방식을 적용

VGG를 통과하며 얻은 피쳐맵을 대상으로 쭉쭉 컨볼루션을 진행하여 최종적으로는 1x1 크기의 피쳐맵까지 뽑음
각 단계별로 추출된 피쳐맵은 Detector & Classifier를 통과시켜 Object Detection을 수행
컨볼루션 중간에 5x5x256 크기의 피쳐맵을 대상으로 Object Detection을 수행한다고 가정
큰바운딩박스로도 예측하고 작은 바운딩 박스로도 예측했다

Default Box란?
Faster R-CNN에서 anchor의 개념으로 비율과 크기가 각기 다른 기본 박스를 먼저 설정해놓아서 Bounding Box를 추론하는데 도움을 주는 장치
고양이는 작은 물체이고 강아지는 상대적으로 더 큼
높은 해상도의 피처맵 -> 작은 물체를 잘 잡아 낼 수 있음
낮은 해상도의 피처맵 -> 큰 물체를 잘 잡아 낼 수 있음
SSD 에서 Default Box 처리
각각의 피쳐맵을 가져와서 비율과 크기가 각기 다른 Default Box를 투영
이렇게 찾아낸 박스들에 bounding box regression를 적용하고 Confidence Level을 계산
YOLO 에서는 아무런 기본 값 없이 2개의 Box를 예측하도록 했었음.. (비교하면 정확도가 훨씬 더 높음)
피쳐맵에 3x3 컨볼루션을 적용하여(패딩을 1로 설정하여 크기 보존) bounding box regression 값을 계산
